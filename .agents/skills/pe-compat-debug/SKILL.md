# Windows PE 兼容性调试

目标是通过证据找到能够解释故障的最小环境差异，不要一开始就复制大量系统文件或套用通用修复。

## 调试环境

- Windows 10 宿主机：`192.168.5.138`，运行 VirtualBox 虚拟机。
- 目标调试 PE：VirtualBox 中的 `WimBuilder2` 虚拟机，地址为 `192.168.5.148`。
- 参考对照 PE：VirtualBox 中的 `Edgeless` 虚拟机，地址为 `192.168.5.164`。
- 三个环境均可通过 LCR 连接。两个 PE 环境中的 LCR 没有命令执行限制；宿主机中的 LCR 仅支持有限命令（`VBoxManage` 等）。若宿主机现有命令权限不足，应向用户请求添加所需命令，不要尝试绕过限制。

## 准备

1. 明确异常 PE、正常对照环境、复现步骤和成功标准。记录系统版本与架构、当前身份、应用版本、安装来源、启动命令和 LCR 地址。
2. 修改仓库前先阅读 `AGENTS.md` 和构建脚本。若存在生成器，应修改构建源并重新生成，不要只改生成产物。
3. 使用 LCR 时完整阅读 `../lcr/SKILL.md`。GUI 和长时间任务使用 `/spawn`，不要同步等待 GUI 进程退出；远程脚本开头不要加 `pause`。
4. 需要调试工具时，先在 `X:\Program Files\Edgeless` 中查找已安装程序；没有时再查询并执行 `ept install <包名>`。安装前确认包名，安装后确认实际路径和版本。

## 调试流程

1. 固定一个最短且稳定的复现步骤。记录时间、完整命令行、工作目录、进程树、退出码、窗口状态和截图。将有符号十进制退出码转换为无符号十六进制后再查询含义。
2. 判断故障类型：进程崩溃、界面异常、其他宿主进程崩溃、卡死或功能静默失败。先确定第一个异常进程以及故障影响范围。
3. 在修改环境前采集证据。优先获取事件日志、崩溃转储、故障模块、进程命令行和模块列表；需要时再使用 Procmon、WinDbg 或 SxSTrace。具体方法见 [tools.md](references/tools.md)。
4. 若有正常 PE，使用相同应用包、操作和时间点采集同类证据。对比文件及版本、注册表、服务、驱动、环境变量、权限和加载模块。
5. PE 环境可以通过重启命令重置到进行某些变更前的状态。执行重启命令前，确保某个盘符下存在 `Edgeless/version.txt`；确认后可以放行重启，并等待 LCR 重新上线，LCR 上线即说明重启已经完成。
6. 根据直接证据提出假设，一次只改变一个变量。修改注册表、文件或权限前保存原状态，并记录完整回滚方法。
7. 使用完全相同的动作复测并重新采集证据。故障表现改变只能说明假设影响了执行路径，不能直接证明问题已经解决。
8. 重启 PE 后再次复测。只有故障消失、目标功能正常且修复能够稳定复现，才视为验证完成。
9. 将最终修复写入构建源，重新生成产物并执行仓库校验。移除临时日志、转储设置和诊断性修改。

## 约束

- 不把猜测当作根因；每项结论都要对应日志、转储、调用栈、追踪结果或可重复的对照实验。
- 不用大范围复制 DLL、导入整片注册表、关闭安全机制或禁用系统组件来掩盖问题。
- 调试工具卡住时先检查调用方式和同步等待，不要立即判断目标应用卡死。
- 大体积日志和转储写入远端文件后下载，不要让 RPC 响应承载全部内容。
- 读取、修改或保存失败时停止该实验，不要继续删除或覆盖原始资源。

## 输出结果

按以下顺序总结：故障表现、已确认事实、关键证据、正常与异常环境差异、验证过的假设、根因、永久修复、重启验证结果、尚未验证的风险。明确区分临时实验与最终修复。
