# PE 调试工具

按证据需求选择工具，不要默认全部运行。先在 `X:\Program Files\Edgeless` 搜索已有工具；缺失时使用 `ept search <关键词>` 确认包名，再执行 `ept install <包名>`。安装后记录可执行文件的实际路径和版本。

## Procmon

用于定位文件、注册表、进程和线程操作中的 `NAME NOT FOUND`、`PATH NOT FOUND`、`ACCESS DENIED` 等异常。

1. 先确定待观察的进程名、安装目录和复现时间。
2. 启动 Procmon 后清空已有事件，只保留与目标进程、相关宿主进程或目标路径有关的过滤条件。
3. 开始捕获，立即执行一次最短复现，然后停止捕获。
4. 保存原始 PML，并导出必要的 CSV 供检索。优先查看故障发生前最后一批失败操作和进程创建/退出事件。
5. 对正常 PE 进行相同捕获并对比。单个 `NAME NOT FOUND` 很常见，只有与执行路径和对照差异一致时才可作为证据。

Procmon 是 GUI 程序，通过 LCR 启动时使用 `/spawn`。不要用同步 `/exec` 等待它关闭。避免长时间无过滤捕获，以免占满内存盘。

## WinDbg

用于分析异常码、故障线程、调用栈、故障模块和进程退出原因。优先分析崩溃转储，必要时再附加实时进程。

1. 为明确的目标进程或宿主进程配置 WER LocalDumps，指定可写且空间充足的目录，并使用完整转储。
2. 复现一次后确认转储文件确实生成；没有转储时检查真正崩溃的进程、WER 可用性和目录权限。
3. 在 WinDbg 中打开转储，首先执行 `!analyze -v`，随后查看异常上下文、故障线程调用栈和加载模块。
4. 记录异常码、故障指令、首个非系统模块、缺失符号情况以及调用链，不要只复制 `!analyze -v` 的结论行。
5. 若需要符号，优先设置微软符号服务器并使用独立缓存目录；PE 无法联网时可将转储下载到宿主机分析。
6. 调试结束后移除临时 LocalDumps 注册项。

若界面整体闪退后自动恢复，应记录相关进程复现前后的 PID；PID 变化可证明实际发生了进程重启，并帮助确定应为哪个进程采集转储。

## SxSTrace

仅在错误、事件或调用栈指向 Side-by-Side、Activation Context、Manifest 或程序集加载时使用。

1. 执行 `sxstrace trace -logfile:<路径>.etl` 开始跟踪。该命令会持续等待，必须异步运行。
2. 复现一次问题。
3. 停止跟踪进程，使 ETL 正常写完。
4. 执行 `sxstrace parse -logfile:<路径>.etl -outfile:<路径>.txt` 转换为文本。
5. 从首个无法解析、找不到或拒绝访问的程序集/清单开始检查，核对文件是否存在、架构与版本是否匹配、目录 ACL 是否允许实际进程身份读取。

不要看到 SxS 错误就整体替换 WinSxS；应修复追踪明确指出的缺失、版本、注册或访问问题。

## 事件日志与转储

没有 Event Viewer 时使用 `wevtutil` 查询 Application、System 和 Windows Error Reporting 附近事件。按复现时间过滤，记录故障应用、故障模块、异常码、偏移和报告 ID。

配置转储时同时考虑可见应用和承载其代码的宿主进程。大文件通过 LCR `/download` 拉回分析；不要直接在命令响应中输出二进制或完整大型日志。

## 对照记录

使用 `项目 | 正常 PE | 异常 PE | 与故障的关联 | 下一步实验` 五列记录差异。只有当单独改变该项能够可重复地改变故障结果时，才能把差异提升为根因。
